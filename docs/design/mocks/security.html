What we store, and what we never see.

Your device indexes and encrypts before anything leaves it. The server receives ciphertext and tokens, and returns them when you search.

The server stores

  • Encrypted transcripts, metadata, notes and recordings
  • HMAC tokens for keywords, contacts and tags
  • Embeddings of redacted text
  • The day of each call and a duration bucket
  • Wrapped keys and public keys

The server never sees

  • Transcript text or individual words
  • Phone numbers or contact names
  • Tag names, notes or rule definitions
  • Your keys, unwrapped
  • Decrypted recordings

Where plaintext goes.

Only when you ask, one request at a time. These routes stream straight through and never write to disk, storage or logs.

Transcription
deviceAskCallsElevenLabs

Audio of a call you upload. ElevenLabs may keep request logs under its standard policy until Zero Retention Mode is in place. With your own key, your device sends it directly and we are not in the path.

Ask about a call
deviceAskCallsAnthropic

That one call and your question, after you agree in a dialog that names the receiver. Anthropic operates under zero data retention. The transcript is wrapped as untrusted data, so instructions inside it aren't followed.

Inbox uploads
remote AI toolAskCallssealed to your key

A transcript a remote AI tool sends for you is visible to our server in transit, sealed at once to your inbox public key, and the plaintext is discarded. The app says so next to each such item.

Unlocking.

Each method keeps its own wrapped copy of the root key. Sign-up can't finish until you create a recovery code and type part of it back.

PasskeyFace ID, Touch ID, Windows Hello or a security key. The PRF extension yields 32 bytes the server never sees.
Recovery code8 groups of 4 characters, shown once. 128 bits of randomness, so no slow derivation is needed.
PassphraseOnly where the browser lacks PRF. Argon2id at 64 MiB, at least 12 characters.
LockingAfter 15 idle minutes and on tab close. Keys and decrypted text are dropped from memory.

Linking a device.

The local agent or another browser receives the root key straight from your existing device, encrypted to a key made for it. The server only relays.

418 602
on the new device
compare
418 602
on your trusted device
  1. In Settings › Devices, choose Link a device to get a short code and a QR code.
  2. The new device makes a key pair and posts its public key.
  3. Both devices show a 6-digit fingerprint. You confirm they match.
  4. The trusted device sends the root key encrypted to the new public key.
  5. The link expires in 10 minutes, is written to the audit log and can be revoked.

Verify what you run.

AskCalls builds reproducibly. Every release publishes the SHA-256 of each client JavaScript asset, so you can check that askcalls.com serves exactly the code in the repository. App routes load no third-party scripts and run under a strict CSP.

~ zsh
$ curl -s https://askcalls.com/_next/static/chunks/app-7f3e2a.js | shasum -a 256
9c1f4e0b7a2d…e81b  -
$ grep app-7f3e2a.js SHA256SUMS-v1.0.0.txt
9c1f4e0b7a2d…e81b  app-7f3e2a.js

The leak test.

0

seeded words and phone numbers found in a full dump of the database and the storage bucket.

Every pull request runs it: seed calls with known words and numbers, dump the entire database and bucket, and search for them in every encoding. If anything turns up, the build fails.

The full threat model sets out what AskCalls protects against and what it doesn't: a compromised device that is unlocked, for example, can read what it shows. Report vulnerabilities as described in SECURITY.md.
